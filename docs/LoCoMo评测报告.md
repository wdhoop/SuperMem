- 评测日期：2026-10-17 ~ 2026-10-18
- 评测规模：**10 段超长多会话对话 / 1986 道 QA 题 / 五类推理**
- 评测环境：本地隔离库（零接触生产库）+ 本地 LLM 作答（9B / 27B / 125B 三档）
- 打分口径：LoCoMo 官方 **Token F1** + **LLM-Judge accuracy** 双口径

## 一、评测方案（可复现）

```
benchmark/
├── data\locomo10.json              # 官方数据集（用户自备，来源见 benchmark/README.md）
├── db\<sample_id>\                 # 10 个隔离评测库（每段对话独立 SQLite + Chroma）
├── scripts\ingest_locomo.py        # 逐轮写入：1 轮 = 1 event 节点 + 逐字原文块 + 自动建边
├── scripts\eval_locomo_{9b,27b,125b}_l24.py   # QA 循环（检索 24+24，积极 prompt）
├── scripts\score_f1.py             # 官方 F1 打分（任意两份结果对比）
├── scripts\judge_accuracy.py       # LLM-Judge accuracy（语义等价判对）
└── results\*.jsonl                 # 全量逐题结果（1986 行/文件，断点续跑产物）
```

**隔离原则**：每段对话一个独立库（`GraphStore(db_path=...)` + `VectorSearch(chroma_dir=...)`），评测零接触生产记忆库，真实个人记忆不会污染检索分数。

**关键适配**：LoCoMo 为全英文对话，评测进程内将 embedding 切换为 **bge-small-en-v1.5**（生产配置的 bge-small-zh 不受影响）。

**官方数据坑**：adversarial 类（446 题）答案标签字段为 `adversarial_answer` 而非 `answer`，已按官方口径兼容。

## 二、成绩总览（limit24 终版，1986 题全量）

| 作答模型 | Token F1 | LLM-Judge Accuracy | unknown 率 |
|---|---|---|---|
| 9B（qwen3.5:9b, Ollama 本地） | 0.4083 | 0.5504 | 314 / 1986 (15.8%) |
| 27B（qwen3.8-27b-fast, Ollama 本地） | 0.4313 | 0.5821 | 88 / 1986 (4.4%) |
| **125B（Qwen3.8-Flash-Next, Strata 本地）** | **0.4585** | **0.6163** | 154 / 1986 (7.8%) |

- F1 与 Accuracy 排序完全一致：**125B > 27B > 9B**。
- Accuracy 全线高于 F1：Judge 允许语义等价（如日期格式不同、同义改写），而 F1 只认 token 重叠。
- **unknown 子集 accuracy = 0.0000（三档一致）**：按官方协议"unknown 一律判错"，模型答 unknown 的题目全部丢分——这是 accuracy 与 F1 差距的主要来源。
- LLM-Judge 使用 DeepSeek V4-Flash（`reasoning_effort=none` 关思考、temperature=0、max_tokens=8、并发 8/断点续跑/5 重试），1986 题全量 err=0。

### 分类别成绩（125B，limit24）

| 类别 | 题数 | Token F1 | Judge Accuracy |
|---|---|---|---|
| multi-hop（跨会话推理） | 841 | **0.6175** | **0.8109** |
| adversarial（对抗/细节） | 446 | 0.4359 | 0.5516 |
| single-hop（单跳） | 282 | 0.4048 | 0.5035 |
| commonsense（常识） | 96 | 0.3552 | 0.5312 |
| temporal（时间推理） | 321 | 0.1515 | 0.3209 |

temporal 是"跨时间推算"问题：检索侧证据命中率高达 86%，但答案多为日期/数值的**词面推算**，token 重叠天然吃亏（证据 86% vs 答案词面 5%），三档模型一致地板 0.12-0.15（125B 0.1515），属于任务本质难题而非检索缺陷。

## 四、核心发现

### 1. 供给量曲线：top-N 名额才是硬瓶颈

同一库、同一 answerer，仅调整检索条数（节点 8/16/24/32 + 原文 8/16/24/32）：

| limit | 证据命中率 | 答案命中率 |
|---|---|---|
| 8 | 65.8% | 34.6% |
| 16 | 77.3% | 41.4% |
| 24 | 82.2% | 44.5% |
| 32 | 84.3% | 46.4% |

边际递减，但**每档都有真实增益**。诊断链佐证：
- oracle 证据 top-8 命中仅 ~50%；补建语义边（`auto_link k=2 min_score=0.40`）后命中率几乎不变（64% vs 64.1%）→ **related 语义边与向量检索高度冗余，名额才是瓶颈**。
- limit 8→24 的 F1 增益随模型增大放大：9B +6.4pp / 27B +6.9pp / 125B +7.7pp → **模型 × 供给是乘法关系**：供给越足，强模型越能兑现。

### 2. 原文层强召回是有效增量

按检索触发模式分组（125B，limit24）：

| 触发模式 | 题数 | F1 |
|---|---|---|
| graph（图检索自信直达） | — | 基线 |
| **hybrid（原文层下探触发）** | — | **高 25~28%** |

凡是系统判定需要下探原文层（verbatim 强召回）的题目，答对质量稳定高出图检索组 +25~28%（在 27B / 125B / DeepSeek 三个 answerer 下均复现）。强召回触发机制（原文向量 top1 > 图向量 top1 时下探）自适应，无绝对阈值依赖。

### 3. 检索-供给是当前瓶颈，不是作答模型

- limit24 下 F1 排序与模型能力排序一致，但**差距全部来自供给而非模型**：供给量翻 3 倍带来的增益（+6~8pp）远大于 9B→125B 换模型（8+8 时仅 +3.7pp）。
- 与社区高分（92%+）的差距主因是**作答模型能力**：社区普遍用 GPT-4.1 / gemini-2.5-pro 级 answerer，本评测用本地 9B-125B。

## 五、与社区成绩对比（口径差异必须注明）

> 重要：**LoCoMo 无官方统一排行榜**，社区全部为自报成绩，且口径不一：
> - 社区主流口径是 **LLM-Judge accuracy**（GPT-4 级模型当 judge，语义等价判对、unknown 判错）；F1 不能直接对比。
> - 社区高分普遍使用 **oracle/近全量上下文**（证据已知或片段已含答案），本评测是**纯检索片段（无 oracle）**，条件更严。
> - 题数口径有差异（官方全量 1986 题 vs 部分社区 1540 题）。

| 方案 | Accuracy（社区自报） | 备注 |
|---|---|---|
| MemoryLake | 94.03% | oracle 检索 + 大模型，社区自报 |
| Mem0 | 92.5% | 社区自报（存在造假争议，MemGPT 作者公开质疑） |
| ByteRover | 92.2% | 社区自报 |
| Backboard | 90.1% | 社区自报 |
| **SuperMem 125B（本评测）** | **0.6163** | **纯检索 + 本地 125B 作答，1986 题全量，脚本结果全公开** |

本评测的立身之本：**完整可复现**（脚本 + 逐题结果 + 数据来源全部公开），不依赖任何自报数字。把 answerer 换成 GPT-4 级模型后，同样的检索供给预计可显著上探（对应官方 RAG 系 0.40-0.50 区间已验证本系统处于中上游）。

## 六、结论与建议

1. **检索系统经官方基准验证可靠**：10 段超长对话（5879 轮/5879 原文块）建成 5 分钟内完成索引，1986 题全量评测 0 LLM 错误、0 崩溃，断点续跑机制有效。
2. **原文层是有效增量**：hybrid 组稳定 +25~28%（三个 answerer 复现）。
3. **供给量是当前最大杠杆**：limit 8→32 连续 4 档均有增益，继续增大供给（更长上下文、更多原文块直灌）是最可能破局的方向。
4. **下一步可选**：
   - 长上下文方案（512K 直灌更多原文块）验证供给上限；
   - 用 GPT-4 级云端 answerer 复测，量化"作答模型能力"对成绩的独立贡献；
   - 交叉验证 LongMemEval 等更长对话基准。
