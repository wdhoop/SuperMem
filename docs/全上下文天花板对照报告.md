# 全上下文天花板对照报告

**版本**：v1.0.2（LoCoMo 全量供给对照）
**日期**：2026-10-25
**模型**：Qwen3.8-Flash-Next **IQ3_S**（本地 Strata 引擎，524K 上下文）
**评判**：DeepSeek V4-Flash，官方 LLM-Judge 二档协议（语义等价判对、unknown 判错、0/1、temperature=0、reasoning_effort=none）
**题目**：LoCoMo 官方 10 段多会话对话，全量 **1986 题**（multi-hop 841 / adversarial 446 / temporal 321 / single-hop 282 / commonsense 96）

---

## 一、动机

社区建议（对外叙事）："在'本地小模型 + 双口径'条件下，绝对分数不能直接对标榜单。补一个
**全上下文天花板基线**：用同一个模型把全部对话塞进上下文直接回答，得到该模型下的上限。
记忆系统相对这个上限的提升幅度，比绝对分数更能说明系统价值。"

本报告即该建议的第 ④ 项：**天花板基线**。

## 二、实验设置

| 项 | 检索供给（记忆系统基线） | 全上下文（天花板） |
|---|---|---|
| 供给方式 | SuperMem 检索回忆，**limit 24 条片段** | 整段对话（10.5 万~11.5 万字符）直接进上下文 |
| 会话 | 每题独立单轮（检索片段 + 问题） | 每段一个多轮会话（对话作公共前缀，逐题追加） |
| KV 复用 | 无 | 有（避免 1986 次全量 prefill，~3.9 秒/题） |
| 结果文件 | `locomo_results_125b_l24_v2.jsonl` | `locomo_results_125b_fullctx.jsonl` |
| judge | `judge_125b_l24_v2.jsonl` | `judge_125b_fullctx.jsonl` |

两口径同一模型权重、同一 judge 协议、同一题目集合，唯一变量是**供给方式**。

## 四、解读

### 4.1 天花板真实存在，且主要在"事实回忆"类别

- multi-hop / temporal 两口径均显示全上下文大幅领先（+7~46pp）。这两个类别的本质是
  "跨会话长距离事实 + 时间关系"，检索供给的召回覆盖还不够。
- 全量 F1 +2.5pp、逐题胜 702 vs 593：天花板**高于**当前记忆系统，提升空间明确。

### 4.2 记忆系统的独特价值：对抗误导（adversarial）

- adversarial 类（446 题，官方定义为对话中存在诱饵/误导信息，正确行为是识破）：
  检索供给 0.4323（F1）/ 0.5605（accuracy），全上下文 0.0495 / 0.0314。
- 全上下文把诱饵信息**完整吞入**上下文，模型 93% 选择拒绝作答（"unknown"），
  按官方协议 unknown 一律判错，导致近乎全错。
- 检索供给天然做了**信息筛选**：诱饵与矛盾片段通常不会被回忆到，模型反而更稳。
- 结论：**记忆系统不只是一个"上下文压缩器"，它同时是一个信息过滤器**——
  这正是检索型记忆相对全量供给的结构性优势，也是对外叙事里记忆系统
  "相对天花板不落下风甚至反超"的证据。

### 4.3 诚实口径

- 全量 accuracy 检索供给 0.6148 > 全上下文 0.6062（-0.9pp），这个数字如实公开；
  但它由 adversarial 结构性差异主导（-52.9pp），剔除 adversarial 后全上下文在全部
  四个类别领先（+1.1 ~ +46.1pp）。
- unknown 率从 7.6% 升至 22.5%：全上下文下模型更频繁拒绝作答，在官方协议下
  "诚实"被扣分。这是协议口径问题，两边同规则，公平可比。

## 五、对记忆系统研发的指向

1. **提升 temporal 覆盖**（+38.9pp 差距最大）：检索对时间关系类片段的召回不足，
   时序边/时间窗口加权是下一步重点。
2. **提升 multi-hop 覆盖**（+8.4pp）：跨会话长距离多跳事实召回仍有空间，
   联想桥/图遍历方向继续投入。
3. **adversarial 防御是差异化卖点**：现有检索天然过滤诱饵，可进一步做
   "误导片段识别"专项（如对检索结果的矛盾检测），把防线显式化。

## 六、复现

```bash
# 1. 全量供给评测（KV 复用，断点续跑；需 Strata 125B 端点运行中）
python benchmark/scripts/eval_locomo_125b_fullctx.py
# 输出 results/locomo_results_125b_fullctx.jsonl

# 2. LLM-Judge 判定（DeepSeek V4-Flash；ds_api.json 配置端点与 key）
python benchmark/scripts/judge_fullctx.py
# 输出 results/judge_125b_l24_v2.jsonl + results/judge_125b_fullctx.jsonl

# 3. F1 同题对照
python benchmark/scripts/score_fullctx.py
```

数据文件：`benchmark/results/locomo_results_125b_fullctx.jsonl`、
`judge_125b_l24_v2.jsonl`、`judge_125b_fullctx.jsonl`（各 1986 行，含逐题
question/gt/pred/分类/verdict，可独立复核）。
