# SuperMem 架构说明

SuperMem 是一个**本地优先的长期记忆系统**：把记忆组织成"图 + 向量 + 原文"三层，写入时自动提取与建边，检索时融合多路信号，运行时自动完成记忆的生命周期管理。

---

## 一、总体分层

```
┌─────────────────────────────────────────────────────┐
│ 接入层                                              │
│   REST API (api.py) │ MCP Server (mcp_server.py)    │
│   CLI 桥接 (bridge/smem.py) │ Web 面板 (web/)        │
├─────────────────────────────────────────────────────┤
│ 检索层                                              │
│   search_fusion.search_strong（融合检索主入口）       │
│   图检索 + 向量检索 + 原文层强召回 + 时间窗 + 因果链   │
├─────────────────────────────────────────────────────┤
│ 写入/提取层                                         │
│   extract / rule_extractor / event_normalizer       │
│   linker(auto_link 建边) / cross_session 聚合       │
├─────────────────────────────────────────────────────┤
│ 生命周期层                                          │
│   node_lifecycle / edge_lifecycle / cycle_detector  │
│   priority_queue / memory_updater / scheduler       │
│   time_window / interrupt_budget / hot_cache / metrics │
├─────────────────────────────────────────────────────┤
│ 存储层                                              │
│   SQLite（nodes/edges/episodes/verbatim/metadata）  │
│   + ChromaDB 向量索引（BGE embedding）               │
└─────────────────────────────────────────────────────┘
```

依赖原则：核心模块全部**只用 Python 标准库**；唯一外部依赖是 ChromaDB（向量索引，惰性加载），embedding 模型按需本地加载。

## 二、数据模型（SQLite 五表）

### nodes —— 记忆节点

| 字段 | 说明 |
|---|---|
| id | 节点唯一 ID（type_日期_随机） |
| content | 记忆内容 |
| node_type | 类型：concept / entity / event / document / rule / episode … |
| status | 状态机：active / archived / obsolete / …（见生命周期） |
| weight | 权重（初始 config.W0），随访问升温、随遗忘衰减 |
| project / tags / source | 归属项目、标签、来源（溯源） |
| confidence | 置信度（1.0 确定，<1 推测） |
| timestamp | 事件时间 |
| version_of / replaced_by | 版本演化指针（去重/更新时维护） |
| marked_until | 显式标记保留到期时间 |

### edges —— 记忆边

| 字段 | 说明 |
|---|---|
| from_id / to_id | 源/目标节点 |
| edge_type | 语义类型：related / causal / temporal / same / version … |
| weight / confidence | 边强度与置信 |
| source | 建边来源（auto_link / manual / rule …） |
| description | 关系描述 |

### verbatim —— 原文层（2026-10 新增）

| 字段 | 说明 |
|---|---|
| vid | 原文块 ID（content 哈希幂等） |
| text | **逐字原文，不压缩不改写** |
| node_id | 关联图节点（双向指针） |
| session / source / ts | 出处元数据（会话、来源、时间） |
| vector | 独立向量索引（可选，with_vector=True 时） |

**设计意图**：记忆节点是"压缩后的理解"，原文层是"逐字的原始事实"。强召回场景下（图检索置信不足时）下探原文，保证信息无损。LoCoMo 评测实证：hybrid（原文下探）组 F1 稳定高出 graph 组 +25~28%。

### episodes / metadata

- `episodes`：会话聚合（把一轮轮对话聚合成"事"），供 `time_window.get_episodes` / 时间线使用。
- `metadata`：系统元数据（schema 版本、统计等）。

## 三、写入链路

```
文本/结构化输入
   │
   ├─ POST /nodes      → Node → add_node_with_vector（去重 dedup）
   │                     → linker.auto_link（相似老节点自动建边）
   │                     → verbatim 落原文层（哈希幂等，node_id 双向指针）
   │
   ├─ POST /extract    → extract.extract_from_text（自动识别概念/事件/规则/心得）
   │                     → 逐条 add_node_with_vector + auto_link
   │                     → 原文逐字落 verbatim
   │
   └─ POST /verbatim   → 直接落原文层（关联 node_id / session）
```

- **提取器**：`rule_extractor.py`（"如果…则…"规则抽取）、`event_normalizer.py`（事件时间归一化）、`cross_session.py`（跨会话同实体聚合）。
- **建边**：`linker.py auto_link` 用相似度/同标签/时间接近度建 `related/causal/temporal` 边；`cycle_detector.py` 检测并打破循环依赖。

---

## 四、检索链路（search_strong 融合检索）

```
query
  ├─ 图检索：向量 top-N 节点 + 沿边扩展（因果/语义邻域）
  ├─ 向量检索：ChromaDB cosine top-N
  ├─ 强召回下探：若"原文向量 top1 > 图向量 top1"（比较型触发信号）
  │    → 取原文层 top-K（verbatim 强召回），补足图检索力所不及的信息
  ├─ 时间窗过滤：time_window 按时间范围/会话聚合裁剪
  ├─ 因果链扩展：CausalEngine BFS 追加 cause/effect 链
  └─ 权重分区排序：Core / Working / Cold 分区加权输出
```

输出结构：`{results: [图节点+边], raw: [原文块], mode: graph|hybrid|err, ...}`，可直接拼装成 LLM 上下文。

## 五、生命周期管理

- **权重与遗忘**：节点权重随 `last_accessed/access_count` 升温；未访问节点按遗忘曲线衰减；低于 `ARCHIVE_THRESHOLD` 转归档/废弃。
- **状态机**：`node_lifecycle.mark_obsolete / mark_outdated`、`edge_lifecycle.clean_dangling_edges`（清理悬空边）。
- **调度**：`scheduler.py` 定时执行回收/备份/清理；`priority_queue.py` 回收队列；`interrupt_budget.py` 中断预算（高频场景防打扰）；`hot_cache.py` 热词缓存；`metrics.py` 统计。
- **一致性**：`VectorSearch.verify_index()` 对账 SQLite 节点与 ChromaDB 向量（缺向量/多向量孤儿检测）；`scripts/rebuild_vector_index.py` 重建。

## 六、REST API（api.py，http.server 标准库）

认证：`Authorization: Bearer <token>`（token 来自环境变量 `SUPERMEM_API_TOKEN`）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康/统计（nodes/edges/vector gap） |
| GET | `/nodes?q=&limit=&project=` | 节点搜索（带 q）/列表 |
| GET | `/nodes/<id>` | 节点详情 + 入边/出边 + 因果链 |
| GET | `/search/<query>?limit=&project=` | 普通检索 |
| GET | `/search/strong/<query>?limit=&project=&force=` | **融合检索（强召回下探）** |
| GET | `/rewind/<ts>/<query>` | 时间旅行：某时刻视角检索 |
| GET | `/timeline/<start>/<end>` | 时间线 |
| GET | `/episodes` `/episodes/<id>` | 会话聚合 |
| GET | `/forgotten` `/metrics` `/sessions` | 遗忘区/统计/会话 |
| POST | `/nodes` | 写入节点（自动建边+落原文层） |
| POST | `/extract` | 批量提取（text/nodes/edges） |
| POST | `/verbatim` | 原文层写入 |
| POST | `/mark` | 节点状态流转 |
| POST | `/decay` | 手动权重衰减 |
| POST | `/episodes/build` | 触发会话聚合 |
| POST | `/selfcheck` `/rebuild` `/backup` | 自检/重建向量/备份 |
| POST | `/sync/apply` | 同步应用（多端合并） |

├── rule_extractor.py       # 规则抽取
├── event_normalizer.py     # 事件归一化

├── node_lifecycle.py       # 节点状态机
├── edge_lifecycle.py       # 边清理
├── cycle_detector.py       # 循环检测
├── memory_updater.py       # 记忆更新
├── time_window.py          # 时间窗/时间旅行/时间线
├── cross_session.py        # 跨会话聚合
├── priority_queue.py       # 回收队列
├── interrupt_budget.py     # 中断预算
├── hot_cache.py            # 热词缓存

├── scheduler.py            # 后台定时任务
